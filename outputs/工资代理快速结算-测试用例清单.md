# 工资代理快速结算测试用例清单

## 一、测试入口顺序

建议按这个顺序测，不要一上来就跑全量：

1. 基础可用性：入口、额度、代理列表、订单列表。
2. 申请人主流程：创建订单、查看详情、查看日志、取消订单。
3. 成功闭环：创建订单、代理接单、代理标记付款、申请人确认到账。
4. 异常分支：代理拒绝、申请人投诉、代理投诉。
5. 凭证链路：申请人上传凭证、代理上传付款凭证、查询凭证列表。
6. 数据核查：订单状态、冻结工资、已用工资、代理金币、日志记录、凭证记录。

## 九、数据核查点

| 核查点 | 触发场景 | 预期 |
| --- | --- | --- |
| 订单主表 | 创建订单后 | 新增订单，状态 `10`，金额、币种、代理、申请人一致 |
| 冻结工资 | 创建订单后 | 冻结金额增加，可用工资减少或进行中工资增加 |
| 状态日志 | 每次状态变更后 | 日志按顺序记录完整状态流转 |
| 凭证表 | 上传凭证/付款/投诉后 | 凭证类型、URL、上传用户正确 |
| 工资额度 | 取消/拒绝后 | 冻结工资释放 |
| 代理金币 | 确认到账后 | 代理金币按 `salaryAmount * salaryToGoldMultiple` 增加 |
| 缓存一致性 | 查询详情/列表后 | Redis 缓存和数据库状态一致，不能出现旧状态 |

## 十、JMeter 对应关系

| JMeter 线程组 | 建议先跑吗 | 用途 |
| --- | --- | --- |
| 运行凭证自检（ticket/agent_ticket） | 是 | 先确认 JMeter 已拿到登录态 |
| 工资交易读接口基准（自动提取订单号） | 是 | 查询类接口冒烟，不主动改订单 |
| 工资交易需求流A：创建后申请人取消 | 是 | 最安全的真实变更流，创建后能回滚到取消 |
| 工资交易需求流B：创建-接单-付款-确认 | 谨慎 | 完整成功闭环，会真实完成订单 |
| 工资交易需求流C：创建-接单-付款-投诉 | 谨慎 | 进入投诉处理中，需要后续运营处理 |
| 工资交易需求流D：创建后代理拒绝 | 是 | 验证代理拒绝分支 |
| 工资交易需求流E：公告与凭证维护接口 | 谨慎 | 会保存公告和凭证 |
| 工资交易需求流F：代理侧投诉 | 谨慎 | 进入投诉处理中，需要后续运营处理 |

## 十一、今天建议先执行的最小闭环

1. 跑 `运行凭证自检（ticket/agent_ticket）`。
2. 跑 `工资交易读接口基准（自动提取订单号）`。
3. 跑 `工资交易需求流A：创建后申请人取消（10-50）`。
4. 跑 `工资交易需求流D：创建后代理拒绝（10-60）`。
5. 如果代理 ticket 已确认无误，再跑 `工资交易需求流B：创建-接单-付款-确认（10-20-30-40）`。

这个顺序最适合今天排障：先证明鉴权和读接口通，再证明低风险状态流转，最后再碰完整完成链路。
