# 2026-09-01 工作记录

## 今日主线

今天围绕“需求包隔离 + 可迁移执行闭环”继续优化 AutoTest AI。核心目标是让平台不要把不同需求、不同脚本、不同报告混在一起，而是按需求包维护资产，并逐步形成可迁移的质量中枢流程。

## 已完成内容

1. 明确需求包分层原则
   - 一个需求包对应一个独立业务需求空间。
   - 需求包内按职责拆分资产：`manifest.json`、结构化测试用例、场景编排、账号模型、证据规则、变量别名、工具脚本和报告。
   - 后续维护时只改对应文件，避免一个文件塞满所有配置。

2. pytest 证据复盘 Skill 化
   - 新增 `skills/pytest-evidence-review/SKILL.md`。
   - 把 pytest 深度证据复盘的规则沉淀为可复用 Skill。
   - Skill 约定 pytest 负责执行后深度复核：HTTP 结果、JMeter/Newman 报告、DB/Redis 证据、运行变量和场景级 JSON 报告。
   - 工资交易只是复杂样例，规则不能写死到工资交易。

3. 编排入口可替换
   - 不把 `outputs/execution-plan.json` 写成永久最高优先级。
   - 改成由 `manifest.json` 的 `orchestration.primary_plan` 声明当前需求包主编排文件。
   - 当前默认是 `outputs/execution-plan.json`。
   - 未来如果出现更高级文件，例如 `workflow-plan.yaml` 或 `business-flow.json`，只需要让 manifest 指向新文件。

4. 场景驱动 pytest 执行器
   - pytest 不再只是平铺执行接口后再归纳结果。
   - 现在会按主编排文件的场景顺序组织用例。
   - 每个场景执行前恢复基础运行上下文。
   - 场景内产生的 `orderNo`、流水号、状态值只服务当前场景，避免多订单串数据。
   - 每个场景执行接口后，立即执行该场景绑定的 DB/Redis 证据规则。
   - 未进入正式编排的用例会按 `scenario_type` 兜底分组，避免漏测。

5. 文档补充
   - README 补充了 pytest 证据复盘、编排入口、场景驱动执行、变量隔离和证据规则绑定的说明。
   - Skill 文档补充了场景变量隔离和按场景绑定证据规则的约束。
